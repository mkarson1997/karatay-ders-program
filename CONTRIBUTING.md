# Contributing

Contributions are welcome, especially around scheduling logic, collision handling, accessibility, testing, structured course data, and export reliability.

Before opening a pull request:

1. Keep changes focused.
2. Test schedule generation and conflict cases manually.
3. Preserve existing behavior unless the change is intentional and documented.
4. Include screenshots for visible UI changes when useful.
5. Explain any new scheduling rule or data-format change clearly.

For larger changes, open an issue first to discuss scope.
